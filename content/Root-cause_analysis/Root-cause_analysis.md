# 根因分析：從事件追溯到系統改善

根因分析（Root Cause Analysis, RCA）是一種以證據重建事件脈絡、理解促成因素與系統條件，並設計可驗證改善措施的方法。它最重要的問題不只是「事情為什麼發生」，還包括「哪些條件讓事件變得可能」「我們能改變什麼」「改變後風險是否真的下降」。本書以跨領域、跨地區資料整理根因分析的歷史、工具、限制與新方向，從醫療、航空運輸、職業安全、製造品質、系統工程與因果科學互相對讀。

全書採卡片盒方式組織：`data/` 保存來源脈絡，`note/` 抽取可重組的論點，`idea/` 形成延伸思考與行動，`term/` 定義核心概念，`moc/` 呈現概念關係。每張卡片盡量聚焦一個概念，並以內部雙向連結互相串接。

## 全書主張

1. **根因不必然是單一、最深層的原因。** 複雜事件通常由多項促成因素與不同層級的條件共同形成。
2. **人為失誤不是分析終點。** 調查應重建當事人當時擁有的資訊、工具、時間、目標與限制。
3. **原因必須由證據支持。** 時間先後、相關性和合理故事都不足以單獨證明因果。
4. **工具必須依任務選擇。** 五個為什麼、魚骨圖、故障樹、FMEA、SEIPS、STAMP 與因果推論回答不同問題。
5. **分析完成不等於風險降低。** 改善措施必須有強度、責任人、資源、期限、效果指標與持續追蹤。
6. **學習需要公平與參與。** 前線工作者、患者與家屬、跨專業夥伴都可能掌握關鍵知識；通報文化必須兼顧安全、隱私與問責。

### 初學者：先理解根因分析在做什麼
先讀[[事件調查必須從責怪個人轉向理解系統如何製造風險]]、[[根因不是唯一最深處原因而是可行動的因果解釋]]、[[根因分析必須區分近因促成因素與上游條件]]，再看[[五個為什麼適合簡單流程追問但不宜強套複雜事故]]與[[魚骨圖用來擴展假設不能證明因果]]。這一路徑建立基本詞彙，並避免把 RCA 誤解為「問五次為什麼找到一個人」。

### 實務工作者：從調查走到改善
閱讀[[美國退伍軍人醫療體系以行動階層比較改善措施的強度]]、[[RCA²要求把根因分析與防止傷害的行動合併設計]]、[[英國病人安全事件回應框架以合比例的系統學習取代一律啟動單一RCA]]、[[澳洲運輸安全調查以多源證據和假設檢驗建立安全因素]]與[[Toyota式A3問題解決把根因分析接到反覆驗證與標準化]]。練習用時間線、證據對照表、改善行動階層與效果指標形成完整閉環。

### 研究者與進階讀者：理解因果與複雜系統
接著讀[[Pearl的結構因果模型區分觀察關聯介入效果與反事實問題]]、[[STAMP把事故理解為系統控制約束失效而不只是事件鏈斷裂]]、[[Rasmussen指出風險管理必須把監管管理與現場操作放進同一模型]]、[[Dekker以日常適應與資源衝突解釋組織如何逐漸漂移至失效]]與[[Perrow指出高度複雜且緊密耦合系統可能產生正常事故]]。這些材料提醒讀者，事故不一定有簡單、線性、單一的因果路徑。

### 跨國比較：方法如何嵌入制度
比較台灣 2024 年重大醫療事故通報制度、日本事故與近失事件資料、英國 PSIRF、澳洲 ATSB、美國 NTSB／VA 與 WHO 指引。新版《倫敦議定書》修訂者與案例脈絡涵蓋英國、義大利、法國、瑞士、美國、澳洲、印度、巴西、西班牙及日本，適合用來理解跨國共同原則與地方制度差異。

## 資料範圍與使用提醒

文獻筆記同時包含同行評審論文、政府與國際組織指引、專業協會資料、方法手冊及重要專書。這些來源的證據性質不同：政策文件描述制度要求，專業指引提供實務框架，研究論文呈現特定樣本中的研究結果，書籍則可能提出理論或案例詮釋。閱讀時應注意發表年份、產業脈絡、國家法規與研究限制；不要把單一地區的程序直接當成全球一致標準。

「根因」在不同專業中沒有完全一致的定義，因此這本書以「直接觸發因素、促成因素、潛在條件、控制缺口、可行動的改善點」作為較明確的分析語彙。所有因果結論都應標示證據與不確定性。

## 關鍵方法檢核

- [ ] 問題與調查範圍是否清楚？
- [ ] 是否保留事件時間線、來源與資料缺口？
- [ ] 是否重建當事人工作時的實際情境？
- [ ] 是否區分事實、假設、推論與未知事項？
- [ ] 是否檢查替代解釋與反證？
- [ ] 是否檢視人員、任務、工具、環境、組織及制度的互動？
- [ ] 是否讓受影響者與前線參與？
- [ ] 改善措施是否優先改變系統條件，而非只增加提醒？
- [ ] 是否有責任人、資源、期限、效果指標與持續追蹤？

## 建議延伸行動

可先選擇一個低風險、可回顧的日常流程，練習畫出時間線與魚骨圖，再挑一項假設查找支持及反對證據。接著設計一個小規模、可逆的改善，記錄實施前後差異。這能讓根因分析從概念閱讀轉成持續反思與系統改善的實踐。相關靈感見 [[把根因分析會議設計成共同學習而非責任審判]]、[[為每個根因假設建立反證欄位以減少確認偏誤]]、[[用個人復盤練習辨識條件而不是陷入自我責備]]。
